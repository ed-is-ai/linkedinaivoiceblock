### Gaps Summary

**Two gaps block the phase goal.**

**Gap 1 — BLOCKER (CR-01 confirmed):** The Export JSON button in `src/dashboard/index.tsx:264-265` is gated on `accounts.length > 0`. The phase goal explicitly states the feature supplies "real human-negatives for the Phase 26 eval" — the core user of this feature is someone running capture on a clean feed (no posts flagged, just collecting negatives). Those users have `accounts.length === 0` and the Export JSON button never renders. The `unflagged` state is correctly loaded (L95) and correctly passed to `handleExportJson` (L131), but `handleExportJson` is unreachable. Fix: change the gate to `(accounts.length > 0 || posts.length > 0 || unflagged.length > 0)`.

**Gap 2 — REQUIREMENTS ORPHAN:** CAPTURE-01, CAPTURE-02, and the Phase 25.1 interpretation of EXPORT-01 are not defined in `.planning/REQUIREMENTS.md`. The implementation is substantially correct, but there is no authoritative requirement document to verify against. REQUIREMENTS.md currently defines EXPORT-01 only for Phase 9 (v1.1) — exporting flagged accounts. The eval-negatives extension is a distinct capability without formal requirements. This makes future traceability and audit impossible.

**Warnings from CR-01 code review (not blocking independently but noted):**

- **WR-02:** Capture opt-in is a `const` captured at `init()` time; toggling in popup has no effect until page reload; no UI hint. Usability gap — the feature appears broken when first enabled.
- **WR-03:** `persistUnflaggedPost` evicts by min-seenAt scan which can evict the just-added entry under clock skew (`oldestIdx` could resolve to 0). The plan's `pop()` strategy (relying on newest-first prepend invariant) is safer.
- **WR-04:** `mergeSettings` read-modify-write race can reintroduce the clobber under rapid concurrent writes. Low-probability in single-user popup but architecturally the same failure class.
