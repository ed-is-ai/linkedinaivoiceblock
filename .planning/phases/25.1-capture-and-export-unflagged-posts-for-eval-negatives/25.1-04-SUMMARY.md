## What Was Built

### Task 1 — Dashboard unflaggedPosts wiring

- Added `UnflaggedPost` to the type import in `src/dashboard/index.tsx`
- Added `const [unflagged, setUnflagged] = useState<UnflaggedPost[]>([])` beside the `posts` state hook
- Added `'unflaggedPosts'` to the single existing `chrome.storage.local.get([...])` array (no second .get call introduced)
- Added `setUnflagged((result.unflaggedPosts ?? []) as UnflaggedPost[])` in the load `.then`
- Changed `handleExportJson` to call `buildJsonExport(accounts, posts, unflagged)` — the third argument carries the captured negatives

### Task 2 — Popup capture opt-in + merge-safe settings

- Imported `Settings` type to replace the inline cast for typed settings reads
- Added `const [captureUnflagged, setCaptureUnflagged] = useState(false)` state hook
- Settings-read effect now reads `s?.captureUnflaggedPosts ?? false` and calls `setCaptureUnflagged`
- Replaced the clobbering `chrome.storage.local.set({ settings: { autoHideThreshold: value } })` in `saveThreshold` with a shared async `mergeSettings(patch)` helper that reads current settings, spreads them, applies the patch, and writes — both `saveThreshold` and new `saveCaptureUnflagged` call it
- Added a labeled checkbox in the `<details>` Settings block bound to `captureUnflagged`, with a clear power-user/privacy hint ("stores text from posts that were NOT hidden — broader privacy surface, OFF by default")
- Added `captureRow`, `captureLabel`, `captureCheckbox`, `captureHint` entries to the `styles` inline style record (no CSS class selector strings added)

### Task 3 — 26-CONTEXT.md amendment

- Added an amendment block under D-09 documenting that Phase 26's eval walker must read BOTH `flaggedAccounts[].posts[]` AND `unflaggedPosts[]`
- Documents entry shape, that unlabeled entries are skipped (consistent with D-09), and that stored scores are re-scored fresh (consistent with D-08)
- Cites Phase 25.1 D-07/D-08 as source; existing D-01..D-09 text unchanged (additive amendment only)
