<objective>
Wire the captured negatives into the user-facing surfaces: (1) the dashboard loads `unflaggedPosts` and includes them in the Export JSON download, and (2) the popup Settings exposes the `captureUnflaggedPosts` opt-in so the user can actually enable the feature (it is OFF by default and useless without a control). Also fix the latent settings-clobber bug and record the cross-phase contract amendment for Phase 26.

Purpose: Without the dashboard read, the captured negatives never reach the export; without the popup toggle, the user can never enable capture. The popup currently writes `set({ settings: { autoHideThreshold } })`, which REPLACES the whole settings object — adding a second field requires switching to a merge so the two settings do not clobber each other.

Output: dashboard load + export wiring; popup opt-in control with merge-safe settings persistence; an amendment note in `26-CONTEXT.md`.

Implements D-07 (export includes the captured negatives end-to-end), D-05 (user-controllable opt-in), D-08 (record the Phase 26 input-contract amendment).
</objective>

| popup UI → Settings write | A multi-field settings object is written from two independent savers (clobber risk) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-25.1-09 | Tampering | popup `settings` write | mitigate | Switch both savers to a merge (`{ ...existing, patch }`) via a shared `mergeSettings` helper so neither field clobbers the other (acceptance criteria forbids a single-field settings write) |
