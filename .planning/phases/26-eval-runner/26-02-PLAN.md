<objective>
Build `scripts/eval.ts`, a Node CLI (run via `tsx`, same toolchain as `scripts/trace-summary.ts`) that reads a labeled Export JSON, re-scores each labeled post fresh through the shared classifier, computes classification metrics across a threshold sweep (35–90 step 5), prints total + average LLM cost, persists results to `eval/results-YYYY-MM-DD.json`, prints a compact paste-able summary line, and exits non-zero on bad input. Wire it as `npm run eval`.

Purpose: Give the project a repeatable way to measure the LLM classifier's precision/recall/F1/accuracy against a real labeled dataset and see the precision/recall curve (threshold sweep, not a single operating point — D-04/D-05). Depends on Plan 01's `src/shared/classifier.ts` being the single source of truth.

Output: `scripts/eval.ts` (new), `scripts/eval.test.ts` (new), and a one-line `package.json` scripts addition.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem → CLI | Untrusted input JSON (malformed, oversized, crafted keys, non-finite numbers) crosses into the CLI |
| environment → CLI | `ANTHROPIC_API_KEY` env var read by the CLI |
| CLI → filesystem | CLI writes `eval/results-YYYY-MM-DD.json` |
| CLI → Anthropic API | post text + API key sent to api.anthropic.com |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-04 | Information Disclosure | API key in results file / stdout | mitigate | Results JSON schema has NO key field by construction; the key is only placed in the request header by classifyPost; progress/summary lines print index+cost only — never the key. Acceptance criteria assert grep-absence of key in stdout/console calls and no key field in results. |
| T-26-05 | Tampering | Untrusted input JSON (null entries, non-finite numbers, prototype-pollution via crafted keys) | mitigate | null/non-object entry guard skips bad entries; `safe()` (Number.isFinite) wraps every numeric field and every metric; the CLI reads only known fields (`text`, `label`, `score`) by name — no `Object.assign`/merge of attacker keys into app objects, so `__proto__` pollution has no sink. |
| T-26-06 | Denial of Service | Oversized post text in API body | accept | Post text is already truncated to 1000 chars at storage time (STATE Phase 7 decision); accept as-is per RESEARCH. |
| T-26-07 | Tampering / Spoofing | Prompt injection via post text manipulating the scorer | mitigate | SYSTEM_PROMPT instructs JSON-only output; adversarial text cannot escape the score/signals schema — worst case is a parse failure routed to the `errored` count, excluded from metrics. |
| T-26-08 | Tampering | Path traversal / accidental overwrite on results write | mitigate | Output path is a fixed `EVAL_DIR` + date-derived filename, not user-controlled; `mkdirSync(recursive)` is idempotent; daily filename limits accidental clobber to same-day re-runs (intended). |
| T-26-09 | Information Disclosure | NaN/null silently corrupting results | mitigate | Every metric denominator guarded; explicit `null` for undefined metrics (never accidental NaN→null via JSON.stringify) — locked by eval.test.ts zero-positive case. |
| T-26-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed this plan (`tsx` already present per RESEARCH Package Legitimacy Audit) — no install surface. |
</threat_model>
