| Boundary | Description |
|----------|-------------|
| service worker → Anthropic API | API key (`anthropicApiKey` from chrome.storage) crosses to api.anthropic.com over TLS |
| shared module → caller | classifyPost receives the key as a parameter; module must not persist or log it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-01 | Information Disclosure | `classifyPost` apiKey parameter | mitigate | apiKey is only placed in the `x-api-key` request header; never logged, never returned in `ClassifyResult`, never written to storage from the shared module. classifier.ts contains no `console.*` of the key (verify by grep absence of `console` near apiKey). |
| T-26-02 | Tampering | Anthropic response parsing | mitigate | Response text is fence-stripped then `JSON.parse`d inside try-reachable flow; score clamped to 0–100; malformed JSON throws and propagates to caller (caller decides). No `eval`, no dynamic execution of response content. |
| T-26-03 | Repudiation / regression | SW refactor behavior drift | mitigate | The 262-test suite incl. `trace.test.ts` T-24-04 (api-key non-leakage in serialized traces) guards the refactor; suite must stay green with no test edits. |
| T-26-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed this plan (per RESEARCH Package Legitimacy Audit) — no install surface. |
