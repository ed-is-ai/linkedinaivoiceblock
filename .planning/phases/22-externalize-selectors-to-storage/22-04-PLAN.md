<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| chrome.storage.local → dashboard render | Dashboard reads selectorRegistry + selectorSessionMisses and renders selector strings as text (not executed). |
| Reset control → chrome.storage.local write | handleResetSelectors overwrites the registry with the bundled seed; a destructive (reversible) write. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-09 | Tampering | reset-to-defaults write | mitigate | Reset requires an explicit two-step inline confirm (idle → confirming → writing); no single-click destructive write. The write restores known-good bundled seed values (buildSeedRegistry), so it can only move the registry to a safe state, never to attacker-controlled data. |
| T-22-10 | Cross-site Scripting | selector strings rendered in the health table | mitigate | Values are rendered as Preact text children (auto-escaped), never via innerHTML/dangerouslySetInnerHTML. A malicious stored value can only display as inert text. |
| T-22-11 | Spoofing / Tampering | onChanged-driven state update in the dashboard | mitigate | The listener is filtered to area === 'local' and the extension's own keys; chrome.storage.onChanged only fires for same-extension writes. No external context can inject state. |
| T-22-SC | Tampering | npm installs | accept | Zero package installs this phase; no icon/UI library added. |
</threat_model>
