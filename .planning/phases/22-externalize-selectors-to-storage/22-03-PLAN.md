<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| registry resolve() → document.querySelector | Resolved candidate value (originating from chrome.storage.local) is passed to querySelector/querySelectorAll/getAttribute/String.includes on live LinkedIn DOM. |
| init() async boundary → observer hot path | The observer must not run before the cache is warm; a race would silently fall back to seed values. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-06 | Tampering / Injection | resolve() value passed to querySelector at consumer call sites | mitigate | querySelector interprets its argument as a CSS selector, not code; a malformed/tampered value raises a catchable DOMException, never executes script. Call sites already operate on a trusted same-extension storage value. No innerHTML/eval introduced. Seed fallback (Plan 02) guarantees a valid selector even if cache is null. |
| T-22-07 | Denial of Service | observer starting before load() (race) | mitigate | init() awaits seedIfNeeded() + load() before startObserving(); resolve() seed-constant fallback covers the worst case so the feed never breaks (regression-safe, SELECTOR-09). |
| T-22-08 | Information Disclosure | winner-rotation persisting selector values | accept | updateCandidate writes only selector strings (no PII) to same-extension chrome.storage.local; no new exposure beyond the existing selectors.ts contents. |
| T-22-SC | Tampering | npm installs | accept | Zero package installs this phase. |
</threat_model>
