# Phase 25: Dashboard Export + README Script - Context

**Gathered:** 2026-06-14
**Status:** Ready for planning

<domain>
## Phase Boundary

Two deliverables over the Phase 24 trace store:
1. An **"Export Traces"** dashboard button that downloads all stored traces as `linkedin-blocker-traces-YYYY-MM-DD.json` (TRACE-04).
2. A **`npm run trace-summary <file>`** Node script that reads that export, prints a per-source/model cost-breakdown table to stdout (TRACE-05), and writes/updates a `## LLM Cost Reference` section in `README.md` (TRACE-06).

In scope: the dashboard button + export builder, the trace-summary script, README section management, and validation/error handling. **Out of scope:** the eval runner (Phase 26, EVAL-01..04 — it evaluates the *detection/posts* export, not the trace export); any change to how traces are captured (Phase 24 owns that).
</domain>

<decisions>
## Implementation Decisions

### Cost computation (the summary)
- **D-01:** `trace-summary` **recomputes** cost from each trace's stored token split (`inputTokens`/`outputTokens`/`cacheCreationTokens`/`cacheReadTokens`) × **current** prices, NOT by summing the stored `costUsd`. The README always reflects today's rates even for old traces (Phase 24 stored the split for exactly this — 24-CONTEXT D-07).
- **D-01a:** The script **reuses the extension's own `computeCostUsd`** (imported from `src/shared/pricing.ts`) rather than re-implementing the formula — map each `TraceEntry`'s camelCase split back to the Anthropic usage shape (`{ input_tokens: entry.inputTokens, output_tokens: entry.outputTokens, cache_creation_input_tokens: entry.cacheCreationTokens, cache_read_input_tokens: entry.cacheReadTokens }`) and call `computeCostUsd(entry.model, usage)`. Single source of truth for the cost math; recompute is guaranteed consistent with capture-time logic. Prices come from the imported `MODEL_PRICING` constant (today's code values).

### Trace export shape
- **D-02:** Export is a **wrapped envelope**: `{ exportedAt: <ISO>, traces: TraceEntry[] }` — matches the existing `buildJsonExport` `{exportedAt, ...}` convention and leaves headroom (e.g. a `version` field). **No** embedded pricing snapshot — the script imports current code prices (pairs with D-01's "README reflects current rates").
- **D-02a:** Add a pure `buildTracesExport(traces: TraceEntry[]): string` to `src/dashboard/dataManagement.ts` (mirrors `buildJsonExport`). Wire `handleExportTraces` in `src/dashboard/index.tsx` reusing the existing `triggerDownload(content, filename, mime)` helper; filename `linkedin-blocker-traces-${today}.json`, mime `application/json`. Read `llbTraces` by adding it to the dashboard's existing `chrome.storage.local.get([...])` call. Add an **"Export Traces"** button next to the existing Export JSON/CSV buttons.

### Error traces in the cost table
- **D-03:** Token/USD columns sum **successful calls only** (real spend). Failed-call traces (those with an `error` field — Phase 24 traces every attempt with 0 tokens/0 cost) are surfaced as a **separate `failed` count** per source+model (a column or footnote), not mixed into the token/cost sums. `avg USD/call` is computed over successful calls. Most accurate spend picture while keeping failure visibility.

### Script runtime + CLI
- **D-04:** The script is **TypeScript run via `tsx`** — `scripts/trace-summary.ts`, invoked as `npm run trace-summary <file>` (`"trace-summary": "tsx scripts/trace-summary.ts"` in package.json; add `tsx` as a devDependency). TypeScript so it can import `computeCostUsd`/`MODEL_PRICING` from `src/shared/pricing.ts` and the `TraceEntry` type from `src/shared/types.ts` (D-01a). Existing scripts are plain ESM `.js`; this one is `.ts` specifically to reuse the shared cost module.

### Table format (stdout + README)
- **D-05:** Group rows by **source + model**. Columns (TRACE-05 locked): source, model, calls (successful), failed, input tokens, output tokens, total USD, avg USD/call. Include a **totals row**. The same table is printed to stdout and embedded in the README section.

### README management
- **D-06:** `README.md` does **not** exist yet. The script **creates it if missing** (scaffold a minimal `# LinkedIn Blocker` heading + one-line description), and if present **idempotently replaces only the `## LLM Cost Reference` section** (from the `## LLM Cost Reference` heading up to the next `## ` heading or EOF — never touch other content). Include a generated-by line: `_Generated by \`npm run trace-summary\` on <date> from N successful + M failed traces._`

### Validation / exit codes (Success Criterion 4)
- **D-07:** The script **exits non-zero with a clear stderr message** when the input file is missing, is not valid JSON, or lacks a `traces` array (or `traces` is not an array). Empty `traces: []` is valid (produces an empty table / a "no traces" note), not an error.

### Claude's Discretion
- Exact stdout rendering (aligned text vs markdown table — markdown is natural since the README needs markdown anyway), the `failed`-as-column vs footnote choice, the `tsx` version pin, and whether to also print a per-source or grand-total summary line.
- Whether `buildTracesExport` lives in `dataManagement.ts` (recommended, alongside the other builders) or a new module.
</decisions>

- `triggerDownload` (index.tsx) + the `buildXExport` builder pattern (dataManagement.ts): "Export Traces" is a 3-line addition mirroring `handleExportJson` (build envelope string → `triggerDownload(..., \`linkedin-blocker-traces-${today}.json\`, 'application/json')`).

- ESM throughout; scripts use `import` + `fileURLToPath` for paths. The new script adds `tsx` to run TypeScript that imports `src/shared/*`.

### Integration Points
- Dashboard: new button + `handleExportTraces` reading `llbTraces` from storage.
- Node CLI: `scripts/trace-summary.ts` ← reads the export JSON, imports `computeCostUsd`/`MODEL_PRICING`/`TraceEntry`, writes README.
- `package.json`: `trace-summary` script + `tsx` devDep.

<specifics>
## Specific Ideas

- README cost table must reflect **current** prices (recompute), not capture-time cost — the README is documentation of today's cost (D-01).
- Failed calls visible but not polluting spend (D-03).
- Self-contained export envelope `{exportedAt, traces}` (D-02); script pulls prices from the code, not the file.
- Reuse the extension's `computeCostUsd` so there is exactly one cost formula in the codebase (D-01a).

</specifics>
