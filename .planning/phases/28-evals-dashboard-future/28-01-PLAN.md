<objective>
Build the additive data-model and storage foundation the Evals page depends on, with zero UI.
This plan ships: the `label?` field on `StoredPost` (D-10), the `evalRuns` storage key (D-03), the
optional `incomplete?` marker on `EvalRun` (D-06), the `EvalRunStore` FIFO persistence module
(D-03), the label write-back functions in `postStore.ts` (D-08/D-09), and the promotion of the
threshold-sweep set `THRESHOLDS` into the shared eval core so CLI and page consume one constant (D-03).

Purpose: Establish typed, tested storage primitives so the page (Plan 02) and run engine (Plan 03)
can consume them without redefining shipped types or reinventing the storage idioms — and so the
threshold sweep used by terminal and UI is a single shared constant that cannot drift.
Output: New `evalRunStore.ts`; additive edits to `types.ts`, `runs.ts`, `metrics.ts`, `index.ts`,
`postStore.ts`, `scripts/eval.ts`.
</objective>
