<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| page → service worker (SCORE_POST) | Post text sent to relay → Anthropic API (existing surface, Phase 26) |
| page → chrome.storage.local | Run records persisted; prior runs read for compare |

The LLM path adds NO new external network surface — it reuses the existing, already-audited SCORE_POST
relay. The page never holds the API key and never fetches Anthropic directly (D-07).

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-08 | Information Disclosure | API key exposure on LLM run | mitigate | Page routes via SCORE_POST relay only; key stays in service worker (Phase 26); no key read/fetch from the page |
| T-28-09 | Denial of Wallet | unbounded LLM spend on large dataset | mitigate | D-05 estimate+confirm modal (explicit approval) + D-06 in-run Cancel are the spend guards (relay is not rate-limited by design, D-07) |
| T-28-10 | Tampering | partial run persisted as if complete (misleading metrics) | mitigate | EvalRun.incomplete flag + visible "partial" marker on metrics (D-06) |
| T-28-11 | Spoofing | XSS via post text / signal names in FP/FN cards | mitigate | Preact escapes text children; render previews/signal names as children, never dangerouslySetInnerHTML |
| T-28-SC | Tampering | npm/pip/cargo installs | accept | No new package installs in this phase — all deps (preact, vitest, pricing/eval core) already shipped; legitimacy gate N-A |
</threat_model>
