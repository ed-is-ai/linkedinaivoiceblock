<objective>
Instrument the 5 live content-script match sites so the 7 contextual Selector Health
targets (`SPONSORED_MARKER`, `COMPANY_PAGE_MARKER`, `OPEN_TO_WORK_MARKER`, `AUTHOR_HEADLINE`,
`CONNECTION_DEGREE`, `COMMENT_TEXT`, `COMMENT_EXPAND_BUTTON`) record a real `lastMatchedAt`
via the existing fire-and-forget `SelectorRegistry.updateCandidate()` pattern — closing the
permanent "—" gap in the dashboard Selector Health "Last matched" column. (SHA-01)

Purpose: Make Selector Health "Last matched" reflect reality for contextual selectors. Today
these 7 targets have no `updateCandidate` call site, so `candidate[0].lastMatchedAt === null`
forever (renders "—"). This plan adds the call sites — and nothing else: no detection-logic,
no scoring, no exclusion-outcome change, no new selector-write surface.

Output: 5 edited content-script files, each adding `updateCandidate(target, resolve(target)).catch(() => {})`
on the truthy match, mirroring `observer.ts` exactly. Build/type-check/tests stay green.

  dispatched via `getExclusionSkills()` at `content/index.ts:390`. `src/content/exclusions.ts`
  is DEAD at runtime (imported only by its test). DO NOT touch `exclusions.ts` — a diff touching
  it for SHA-01 is a red flag.
- Only `SelectorRegistry` writes selector strings. These files only CALL `updateCandidate`;
  they must NEVER `storageSet({ selectorRegistry })` directly.
- `nonEnglishExclusionSkill` is NOT instrumented — D-03 lists exactly 7 selectors; non-english
  has no contextual selector target (delegates to `isNonEnglish()` using lang/codepoints).
