<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Anthropic API (x-api-key header) → service worker | The API key lives only in the fetch request header; it must never flow into a TraceEntry |
| service worker → chrome.storage.local (llbTraces) | Local-only persistence; nothing transmitted this phase |
| post text / DOM skeleton → userPrompt field | Untrusted page-derived content, bounded to 500 chars |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-04 | Information Disclosure | Anthropic API key | mitigate | The key is read into a local `apiKey` variable used only as the `x-api-key` header; no TraceEntry field accepts it. trace.test.ts case (4) asserts the seeded key string is absent from serialized `llbTraces`. This is a must_have. |
| T-24-05 | Information Disclosure | detector `userPrompt` (post text, PII-ish) | mitigate | Truncated to 500 chars at the call site (`postText.slice(0,500)`); local-only, never transmitted in Phase 24. Consistent with existing opt-in storedPosts persistence. |
| T-24-06 | Information Disclosure | rederiver `userPrompt` (DOM skeleton) | accept | Phase 23 already strips all text/href/src/aria-label before the skeleton is built, so it carries no PII; storing it (truncated to 500) discloses only structural tag info. |
| T-24-07 | Tampering | npm/pip/cargo installs | accept | No new dependencies; uses Plan 01 modules + existing vitest harness. No install task → no slopcheck surface. |
| T-24-08 | Denial of Service | unbounded `llbTraces` growth | mitigate | FIFO cap 500 (Plan 01 `appendTrace`); verified end-to-end by trace.test.ts case (5). |

(No package installs in this plan; package legitimacy gate not triggered.)
</threat_model>
