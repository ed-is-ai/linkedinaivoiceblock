<objective>
Add the content-script side of the manual heal: a new `chrome.runtime.onMessage` listener in `src/content/index.ts` that, on a `TRIGGER_HEAL` message, resolves the LIVE feed container fresh, runs the generalized `triggerHeal` under the EXISTING single-flight + cool-off guard, and responds with the per-target `HealOutcome[]` (HEAL-02 / D-02, HEAL-05 / D-08, D-09).

To prevent two independent latches (which would let a manual click run concurrently with an automatic heal), extract a single exported guarded entry point from `observer.ts` and have BOTH `onZeroPostsFound` and the new listener call it (D-08).

Purpose: Give the dashboard a content-side endpoint that runs the real heal against the live DOM only, sharing the automatic trigger's stampede protection, and signaling a busy decline with the pinned `HEAL_BUSY` sentinel.
Output: One exported guarded heal entry in `observer.ts`; the first content-script `onMessage` listener in `index.ts`.
</objective>
