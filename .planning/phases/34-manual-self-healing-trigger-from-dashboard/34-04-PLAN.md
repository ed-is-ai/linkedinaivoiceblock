<objective>
Add the dashboard side of the manual heal (HEAL-01 / D-01, HEAL-04 / D-06): a "Heal selectors now" button in the Selector Health section that is enabled only when a `linkedin.com/feed` tab is open (otherwise disabled with a hint), sends `TRIGGER_HEAL` to that tab via `chrome.tabs.sendMessage`, displays the per-selector outcome, distinguishes a busy/cool-off decline via the pinned `HEAL_BUSY` sentinel, and lets the Selector Health rows refresh from storage.

Row refresh is FREE — heal writes go through `insertCandidate` → `storageSet({ selectorRegistry })`, and the existing `chrome.storage.onChanged` effect already re-renders the rows (D-06 half satisfied).

Purpose: Expose the heal pipeline as a user-driven action with clear enablement and outcome feedback, reusing the existing component and styling (no new design system).
Output: Manifest verified/updated for `chrome.tabs.query({url})`; `handleHeal` + `feedTabOpen` in `index.tsx`; heal button + result rows in `SelectorView.tsx`.
